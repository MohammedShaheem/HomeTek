# HomeTex (HENIEMO)

A Django-powered home textiles informational website with a fully admin-controlled CMS. Content editors manage pages (About, Why Choose Us, Company Profile, Blog, Product Categories, Contact) directly through the Django admin, with no need to touch templates for routine content updates.

## Tech Stack

- **Backend:** Python / Django
- **Database:** MySQL
- **Frontend:** Django Templates + Tailwind CSS v4 (standalone CLI, no Node.js required)
- **Fonts:** Baloo 2 (headings), Quicksand (body)
- **Brand colors:**
  - `brand-red` — `#e33b4e`
  - `brand-dark` — `#1a1a1a`
  - `brand-gold` — `#B8934F`

## Local Setup

### 1. Clone the repository

```bash
git clone https://github.com/MohammedShaheem/HomeTek.git
cd HomeTek
```

### 2. Create and activate a virtual environment

**Windows (PowerShell):**
```powershell
python -m venv env
.\env\Scripts\activate
```

**Mac/Linux:**
```bash
python3 -m venv env
source env/bin/activate
```

### 3. Install Python dependencies

```bash
pip install -r requirements.txt
```

## Environment Variables

Create a `.env` file in the project root (or configure equivalent values directly in `settings.py` depending on your setup) with values such as:

```
SECRET_KEY=your-django-secret-key
DEBUG=True
ALLOWED_HOSTS=127.0.0.1,localhost

DB_NAME=hometex_db
DB_USER=your_db_user
DB_PASSWORD=your_db_password
DB_HOST=127.0.0.1
DB_PORT=3306
```

Set `DEBUG=False` and update `ALLOWED_HOSTS` appropriately before deploying to production.

## Database Setup

This project uses **MySQL**. Ensure a database is created before running migrations.

```sql
CREATE DATABASE hometex_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

Then run migrations:

```bash
python manage.py migrate
```

Create an admin user to access the Django admin panel:

```bash
python manage.py createsuperuser
```

> **Note:** If you encounter a `ValueError` related to unloaded timezone tables (a known MySQL + Django timezone issue), make sure MySQL's timezone tables are loaded (`mysql_tzinfo_to_sql`) or set `USE_TZ = False` in `settings.py` depending on your deployment environment's requirements.

## Static Files & Tailwind CSS Build

This project uses **Tailwind CSS v4** via the **standalone CLI** — no Node.js, npm, or `django-tailwind` package required. The CSS is compiled locally by the developer and the finished, production-ready CSS file is **committed directly to the repository**. The hosting/deployment environment does not need to install or run any Tailwind-related tooling.

### How it's configured

- **Source file:** `static/src/input.css` — contains the Tailwind import and the custom `@theme` block (brand colors + fonts):

  ```css
  @import "tailwindcss";

  @source "./templates";
  @source "./**/templates";

  @theme {
    --color-brand-red: #e33b4e;
    --color-brand-dark: #1a1a1a;
    --color-brand-gold: #B8934F;

    --font-sans: "Quicksand", "Helvetica Neue", Arial, sans-serif;
    --font-heading: "Baloo 2", "Quicksand", sans-serif;
  }
  ```

- **Compiled output:** `static/css/tailwind.css` — the actual file linked in `base.html` and served to browsers:

  ```html
  {% load static %}
  <link rel="stylesheet" href="{% static 'css/tailwind.css' %}">
  ```

- **Build tool:** `tailwindcss.exe` (Windows standalone binary) — **not committed to git** (listed in `.gitignore`). This is a local development tool only; it is never required in production.

### Rebuilding the CSS (only needed if templates/classes change)

If you add new templates or new Tailwind utility classes, the CSS must be rebuilt so the new classes are included in the compiled output.

1. Download the Tailwind standalone CLI for your OS from the [official releases page](https://github.com/tailwindlabs/tailwindcss/releases/latest) if you don't already have it locally. For Windows:

   ```powershell
   curl -sLo tailwindcss.exe https://github.com/tailwindlabs/tailwindcss/releases/latest/download/tailwindcss-windows-x64.exe
   ```

2. Run the watcher while developing (auto-rebuilds on save):

   ```powershell
   .\tailwindcss.exe -i .\static\src\input.css -o .\static\css\tailwind.css --watch
   ```

3. Before committing/pushing, generate the final minified build:

   ```powershell
   .\tailwindcss.exe -i .\static\src\input.css -o .\static\css\tailwind.css --minify
   ```

4. Commit the updated `static/css/tailwind.css` file.

### Important for whoever deploys/hosts this project

- **No build step is required in production.** `static/css/tailwind.css` is already compiled and committed — it's deployed like any other static asset.
- Do **not** re-add the Tailwind CDN script (`<script src="https://cdn.tailwindcss.com">`) to `base.html` — it was intentionally removed since the CDN build is not suitable for production and now duplicates the compiled CSS.
- If templates change in the future and new Tailwind classes are needed, that requires the Tailwind CLI to be run locally by a developer and the resulting CSS file re-committed — it is not something the hosting environment needs to handle.

## Running the Project Locally

Open two terminals:

**Terminal 1 — Tailwind watcher (only needed if actively editing templates/styles):**
```powershell
.\tailwindcss.exe -i .\static\src\input.css -o .\static\css\tailwind.css --watch
```

**Terminal 2 — Django development server:**
```powershell
.\env\Scripts\activate
python manage.py runserver
```

Visit `http://127.0.0.1:8000/` in your browser.

## Deployment Notes

- Set `DEBUG=False` in production settings.
- Update `ALLOWED_HOSTS` with the production domain.
- Run migrations on the production database:
  ```bash
  python manage.py migrate
  ```
- Run `collectstatic` to gather all static files (including the pre-built `tailwind.css`) into `STATIC_ROOT`:
  ```bash
  python manage.py collectstatic
  ```
- Ensure the production web server (e.g. Nginx/Apache) is configured to serve files from `STATIC_ROOT` at the `STATIC_URL` path.
- No Node.js, npm, or Tailwind CLI installation is required on the production server.

## Notes for Future Contributors

- This project intentionally avoids a Node.js-based frontend build pipeline to keep the deployment footprint simple for a Django-only hosting environment.
- Design philosophy favors clean, minimal layouts over decorative elements — when adjusting UI, prefer simplifying over adding visual complexity.
- Custom brand theme (colors, fonts) lives entirely in `static/src/input.css` under the `@theme` block — update it there rather than reintroducing a `tailwind.config.js`, which is not used in Tailwind v4.
